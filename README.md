# PhyCo Gravity 1000

[中文说明](README.zh-CN.md)

**1,000 synthetic RGB videos across four gravity levels, grouped into 250 base scenes.**
This dataset was generated by primorLee using [PhyCo-Sim](https://github.com/nnsriram97/phyco-sim)
at commit `bd8a3b4eb54fa1ad008250e2033a1f8369bff6d3`, with gravity settings, paired seeds,
gravity-aware prompts, first-frame exports, and physics-state exports added for this collection.
It is a separate dataset generated with that pipeline, not the official PhyCo-Sim dataset.

The full dataset is available in [Release v1.0.0](https://github.com/primorLee/phyco-gravity-1000/releases/tag/v1.0.0).
The five archive parts total **4,756,459,520 bytes (4.43 GiB)**. The data license is
**CC BY-NC 4.0**; the original extraction utility is MIT-licensed.

## Contents

| Item | Value |
|---|---|
| RGB samples | 1,000 |
| Gravity | 0.1g, 0.3g, 0.5g, 1g; 250 samples each; 1g = 9.8 m/s² |
| Base scenes | 250; four gravity variants per base scene |
| Scene families | Eight: rigid/soft falling balls, soft cube deformation, sliding, forced sliding, Jenga, billiards |
| Train / heldout | 800 / 200 videos; 200 / 50 base scenes; no base-scene overlap |
| Video format | 768 × 432, 24 fps; 752 videos have 98 frames and 248 have 97 |
| Annotations | Prompts, first frames, RGB frames, segmentation/depth outputs, physics states and simulation metadata |
| Archive files | 207,008 files; the 3,000 MP4 files include RGB and auxiliary videos, not 3,000 independent samples |

`dataset_info.json` contains the full family counts and dataset statistics.
`manifests/all.jsonl`, `manifests/train.jsonl`, and `manifests/heldout.jsonl` contain 1,000,
800, and 200 records respectively. Their paths are relative to the extracted data directory.

## Download and extract

Download all five `phyco-gravity-1000.tar.part*` files from the public Release into a
directory named `parts`. GitHub CLI users can run:

```bash
gh release download v1.0.0 --repo primorLee/phyco-gravity-1000 --pattern "phyco-gravity-1000.tar.part*" --dir parts
python extract_dataset.py --parts parts --output data
```

The extractor requires **Python 3.10+ and no third-party packages**. It verifies every part
and the combined archive before extracting, streams the parts without creating another
large TAR file, and requires a new or empty output directory. Reserve approximately
10 GiB for the downloaded parts and extracted files together.

Part order, sizes and SHA-256 hashes are in `distribution.json` and `SHA256SUMS`.
The SHA-256 of the combined archive is:

```text
b91b2f5b8bf6e4a983b65ac229eec006b42a060d10f21e2874bf62b1b42fb8d6
```

## Read a sample

```python
import json
from pathlib import Path

data_root = Path("data")
with Path("manifests/train.jsonl").open(encoding="utf-8") as stream:
    sample = json.loads(next(stream))

video = data_root / sample["video"]
first_frame = data_root / sample["first_frame"]
prompt = sample["prompt"]
gravity = sample["gravity_scale"]
```

Each sample directory also retains `physics.json`, `physics_states.npz`, `visibility.json`,
original metadata and completion records. Use the repository's portable manifests: some
original metadata and manifests inside the archive retain paths from the generation machine.
The archive's original README predates this public release; this repository is the current
source for download instructions and licensing. The extraction utility does not deserialize
the archived pickle files.

## Provenance and limitations

Generation follows the scene and parameter sampling of the fixed PhyCo-Sim version above.
Textures and HDRIs use a cached subset of Poly Haven assets, not a complete copy of the
upstream authors' asset collection. See [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)
for source attribution and licenses.

- A shared seed and scene configuration do not guarantee pixel-identical initial frames.
  `jenga_force_0010` showed first-frame configuration differences across gravity variants.
  Experiments requiring identical initial states should screen their pairs.
- The renderer may reuse frames after objects settle; consult sample metadata.
- Videos retain their original frame counts and 24 fps. Training-specific cropped caches
  and model weights are not included.
- File integrity, decoding and split checks do not constitute full human acceptance of
  every video or physical trajectory. The public release additionally verifies all archive
  checksums, file counts, safe archive paths and portable manifest references.
- The heldout split separates base scenes. It does not establish generalization to new
  scene families, materials, simulators or real-world physics.
